# 外置引擎模块翻译接入规范

> 目标：在外置引擎模块中消费 TYN 已发现并选中的译表。本文只定义翻译接入需要增加的声明和模块侧工作，不替代模块原有的扫描、设置、存档或文件导入协议。
>
> 清单基线按 2026-11-22 检查到的 `upstream/main`（`4704d757`）：已有 `protocol`、`label`、`scan`、`settings`、`saves`、`fileImports` 等字段。翻译分支在这些字段上增加翻译声明；更新模块清单时保留原有字段和值。

## 1. 需要增加的声明

动态发现的模块在 `res/raw/tyranor_runtime.json` 中增加两个字段：

```json
"capabilities": ["translation"],
"translationRule": "mtool-json"
```

完整清单示例（其余可选块按模块原有需要保留）：

```json
{
  "protocol": 1,
  "label": "Example Runtime",
  "scan": {
    "match": "all",
    "extensions": [".example"],
    "markers": ["game.dat"]
  },
  "settings": {
    "version": 1,
    "items": [
      { "key": "vsync", "type": "boolean", "title": "VSync", "default": true }
    ]
  },
  "saves": {
    "version": 1,
    "directory": "Save"
  },
  "fileImports": {
    "version": 1,
    "items": [
      { "key": "patches", "title": "Import patches", "directory": "patches", "multiple": true }
    ]
  },
  "capabilities": ["translation"],
  "translationRule": "mtool-json"
}
```

`settings`、`saves`、`fileImports` 均为上游已有的独立可选字段；模块没有相应功能时可以省略。增加翻译声明时不要删改这些既有字段。`settings` 对应的 `SETTINGS` 启动参数与翻译 URI 是两项独立输入，模块应分别处理。

| 字段 | 翻译接入要求 |
| --- | --- |
| `capabilities` | 支持翻译时包含 `"translation"`；不支持时省略。 |
| `translationRule` | 指向 TYN 主 App 已注册的译表发现规则。当前可用值为 `mtool-json`。 |

两个字段必须匹配：只有声明 `translation` 且 `translationRule` 已注册，TYN 才会为该模块的游戏开放译表选择。规则 ID 仅是规则选择，不会把解析器代码从模块下载或动态加载到 TYN。

如果模块由 TYN 的固定外置模块适配器注册，而非通过 `tyranor_runtime.json` 动态发现，规则 ID 由 TYN 侧 `ExternalEngineModule.translationRuleId` 指定；模块 APK 仍按本文消费启动 URI。

## 2. 现有清单字段保持不变

以上游当前的模块清单为基线，翻译接入只增加两个声明：

- `protocol`、`label`、`scan`：保持原模块协议与游戏识别规则。
- `settings`：保持模块单游戏设置声明及其 `SETTINGS` 启动参数。
- `saves`：保持模块声明的游戏内存档目录。
- `fileImports`：保持模块声明的游戏目录文件导入项。
- `capabilities`、`translationRule`：翻译接入新增字段。

翻译字段不替代或改变其他能力。对于没有翻译声明的旧模块，TYN 不应发送译表 URI，模块按原方式启动。

## 3. 主 App 与模块的分工

**TYN 主 App：**

- 按 `translationRule` 发现译表、解析格式、显示候选项并按游戏保存选择。
- 启动时把选中的译表规范化为 UTF-8 JSON 字符串 map，通过只读 URI 临时授权给模块。
- 监听源文件写入、替换、创建和删除，并通过 URI 通知消费者有更新。
- 统一维护源格式的解析器与发现规则。

**外置模块：**

- 读取启动 Intent 中可选的 URI；没有 URI 时继续正常启动、显示原文。
- 将 map 接入本引擎的文本显示路径。查表键是原文，未命中时显示原文。
- 监听 URI 变化并重新读取完整 map；更新当前显示内容时用原文重新匹配，再由本引擎适配器重绘。
- 结束游戏会话时注销观察器并停止轮询。

模块不扫描原始译表、不读取 TYN 私有目录、不自行解析源文件格式、不保存 URI 授权，也不应修改或向游戏目录复制文件。引擎钩子、控制码处理、原文恢复和重绘由模块自己维护。

## 4. 启动 URI 协议

用户选择了有效译表后，TYN 在显式启动 Intent 中传入：

| 项目 | 协议 |
| --- | --- |
| Extra key | `com.tyranor.runtime.extra.TRANSLATION_MAP_URI` |
| 类型 | URI 字符串 |
| URI | `content://<TYN applicationId>.translationmaps/session/<token>`；模块必须使用收到的值，不拼接 URI，也不依赖 token 格式。 |
| 访问方式 | `contentResolver.openInputStream(uri)`；内容为 `application/json`、UTF-8、平面字符串 map。 |
| 授权 | Intent 带只读 URI 授权和 `ClipData`；该授权不是持久授权，不调用 `takePersistableUriPermission`。 |
| 未传 URI | 没选译表、模块未声明支持或译表不可用；按原文运行，不作为启动错误。 |

接收示例：

```kotlin
private const val EXTRA_TRANSLATION_MAP_URI =
    "com.tyranor.runtime.extra.TRANSLATION_MAP_URI"

val translationUri = intent.getStringExtra(EXTRA_TRANSLATION_MAP_URI)
    ?.takeIf(String::isNotBlank)
    ?.let(Uri::parse)
```

每次游戏启动都读取当次 Intent。不要把 URI 当作永久文件路径、写入模块配置，或转交给其他应用。译表读取和 JSON 解析放后台线程；无 URI、授权失败或读取失败不能阻断游戏启动。

## 5. 译表格式与更新

当前 `mtool-json` 的源文件是平面 JSON 对象，例如 `"Hello": "你好"`。TYN 将其规范化后通过 URI 提供；模块只需读取 `原文 -> 译文`，不应依赖源文件名、原始路径或存储位置。嵌套对象/数组不作为有效译表。

模块用 `ContentObserver` 订阅收到的 URI。收到通知后重新打开 URI并读取完整 map；通知不携带译文内容。TYN 还提供 `revision` 查询列用于去重和补漏：

```kotlin
contentResolver.query(uri, arrayOf("revision"), null, null, null)?.use { cursor ->
    if (cursor.moveToFirst()) {
        val revision = cursor.getLong(cursor.getColumnIndexOrThrow("revision"))
    }
}
```

建议在 observer 通知之外，每约 **10 秒**查询一次 `revision` 作为兜底；revision 改变时重新读取 URI。通知到达时应直接重读，即使 revision 未变也不要忽略。不要自行轮询游戏目录或译表源文件。

对热更新，模块先解析完整的新表，再原子替换内存 map。要让正在显示的消息也更新，模块必须保留或恢复该消息的原文，以原文键重新查表并调用引擎重绘；不能拿旧译文继续匹配。修改、添加和删除当前选择文件里的译文均应生效，删除后恢复原文。更换 TYN 中选中的译表文件在下次启动时生效；当前 URI 绑定的是启动时选中的文件。

## 6. 新译表格式如何接入

若模块自己的译表不是 `mtool-json`，接入需要分成两部分：

1. **TYN 主 App 增加格式解析器和发现规则**，并注册一个稳定规则 ID。
2. **模块声明该规则 ID**，再按统一 JSON map URI 接收译文并实现自己的引擎文本适配。

模块只改 `translationRule` 字符串不能让 TYN 识别新格式。解析器把源格式归一为统一 map 后，各外置模块消费同一种 URI 协议；引擎间不同的部分仍由模块适配器实现。

## 7. 最小验收项

- [ ] 保留模块原有 `protocol`、`label`、`scan`、`settings`、`saves`、`fileImports` 等声明，只增加翻译字段。
- [ ] 无选择或无 URI 时，模块照常启动并显示原文。
- [ ] 有效选择时，模块能读取 URI 并将译文应用到引擎文本。
- [ ] 修改、添加、删除译文后能收到通知并加载新 map；当前消息按原文重新匹配和重绘。
- [ ] 全程不修改、不新增、不删除游戏目录文件。
- [ ] 游戏退出后观察器和轮询停止；译表访问失败不导致游戏退出。
