# 翻译工作台首期实现说明

状态：本文记录当前项目基础及已接入的 RPG Maker 文本提取代际。提取器按格式代际分别注册；支持范围不代表对所有游戏修改版、封包或加密变体完成兼容验收。服务档案的当前协议列表见[翻译服务配置与协议适配实现说明](翻译服务配置与协议适配实现说明.md)，批量任务见[翻译批量任务实现说明](翻译批量任务实现说明.md)。

## 首期范围

- 工具页的「翻译工作台」入口进入独立二级页；列表以 Room 汇总状态展示一张项目卡片。
- 添加项目使用 TYN `AppBottomSheet`；操作和游戏引擎用 Miuix 下拉项，目录/文件来源以 `AppNavItem` 整行展示路径并打开 SAF 选择器，不再显示项目格式选项；操作摘要以单行说明用途，抽屉底部仅保留添加主按钮，通过点击遮罩或系统返回关闭。只有提取可选引擎，翻译和校对时引擎置灰；项目文件按扩展名/MIME 自动识别，当前只导入 MTool JSON。
- 来源为通过 SAF 授权的 RPG Maker MV/MZ、2000/2003、RGSS 游戏目录，或 MTool JSON 原文/译文映射。项目数据保存在 `translation_workbench.db`，当前 schema v11；项目状态（NEW/PROCESSING/READY/PAUSED/FAILED）与条目、任务状态分别保存。v10→v11 为服务档案增加 `custom_parameters_ref`，请求头/请求体参数值仍只放翻译域安全存储。成功写出 JSON 后记录格式、目标显示名、条目数和时间，导出弹窗内的「导出记录」入口可查看历史；不保存目标 URI。服务表保存非敏感配置和密文引用。删除项目会级联删除该库内的项目、条目、任务和导出记录，不删除也不写入游戏目录。
- 项目卡片固定显示提取、翻译、校对阶段和数据库汇总的进度；导出只在存在条目且没有排队/运行任务时启用。刚添加但尚未提取的游戏项目没有可导出内容，按钮置灰；含条目的导入项目可直接导出。导出格式固定为 MTool JSON，弹窗只选择保存目录；导出历史从弹窗查看。失败提示放在进度条上方的状态行，替代“等待提取”等普通状态，不额外占用一行；项目、术语表和术语删除确认使用 Miuix `OverlayDialog` 并置于 `MiuixScaffold` 宿主内，删除按钮在上、取消按钮在下。术语编辑弹窗的保存及删除确认都会立即持久化；详情页使用 Miuix Scaffold 浮动加号按钮添加术语，不占据底部操作行；不提供“保存并返回”或退出确认，术语表名称变更会在返回时自动保存。
- 工作台列表在手机上最大宽度为 760dp，在平板上扩展到 1440dp 并居中；平板的添加项目与术语表入口并排，项目阶段、进度及操作继续在单张横向卡片中展示，标题、正文、阶段标签和卡片内边距按宽屏调整。
- 翻译工作台的任务语言设置、AI 校对语言与译文编辑、术语表编辑，以及翻译服务配置和高级设置中的文本输入统一使用 Miuix `TextField`。术语表管理和术语详情在手机上单列、平板上双列展示卡片，名称输入与列表标题横跨整行；术语表管理使用浮动加号按钮新建；术语表卡片以名称、术语数量和分隔线组织编辑/删除操作；术语卡片以独立底色块展示原文与译文，不显示条目序号，较小字号的备注行置于下方，标签列和正文列分别与上方两行对齐；右侧编辑与删除按钮保持原尺寸，在原文/译文区域内垂直居中且等距；各字段单行省略。
- MV/MZ 提取任务由 WorkManager 持久队列串行执行。Room 保存任务状态、文件总数、完成数和文件检查点；单个文件的条目结果、项目 revision 与检查点在同一事务提交。用户取消和任务失败保留已提交条目；取消或失败后可从检查点创建继续任务。应用启动后进入工作台时会补排仍可运行的任务。
- Worker 运行时使用 WorkManager `SystemForegroundService` 的 `dataSync` 前台类型和低打扰通知。Android 通知设置、系统省电/任务限制、用户强制停止等仍可能影响通知展示和后台执行；Room 检查点是恢复依据。

## RPG Maker MV/MZ 提取器

两个引擎各有独立注册项和 extractor ID：

| 引擎 | `extractorId` | `formatVersion` | 输出 schema |
|---|---|---|---:|
| RPG Maker MV | `rpgmaker-mv-json-v1` | `mv-json-data-v1` | 1 |
| RPG Maker MZ | `rpgmaker-mz-json-v1` | `mz-json-data-v1` | 1 |

当前共享的 JSON reader 只处理未加密、未封装的 `data/` 或 `www/data/` 直接子目录，且需发现 `System.json`。允许的数据库文件为 `Actors.json`、`Animations.json`、`Armors.json`、`Classes.json`、`CommonEvents.json`、`Enemies.json`、`Items.json`、`MapInfos.json`、`Skills.json`、`States.json`、`System.json`、`Tilesets.json`、`Troops.json`、`Weapons.json`，另支持 `Map数字.json`。

- 数据库提取白名单覆盖名称、说明、昵称、简介、数据库消息等已知文本标量，以及 `terms` 下的字符串和 `basic`、`commands`、`params`、`messages`、`choices` 文本数组。
- 地图及公共事件按 JSON 中的已知命令码提取说话人名（101）、选项（102）、对话（401）、滚动文本（405）和角色名称/昵称/简介命令（320、324、325）。未识别命令参数不作为文本扫描。
- `note`、`script`、`parameters` 明确跳过；不会执行游戏脚本，也不会调用插件。
- 单个 JSON 文件最多读取 32 MiB；相对路径拒绝绝对路径、反斜杠、`.`、`..` 和冒号段。读取只经 SAF 授权树的只读接口完成。
- `sourceKey` 由相对文件路径和 JSON Pointer 组成（`<relative-file>#<pointer>`），定位不同的同文条目不会合并。相同来源键重提取时保留原译文；原文变化时清空旧译文。

尚未覆盖的内容包括归档或加密游戏、插件自定义数据与插件参数、JavaScript/脚本文件、图片内文字、运行时生成文本、未列入白名单的 MV/MZ 字段以及其它 RPG Maker 代际。支持上述目录结构不等于兼容所有 MV/MZ 版本或游戏修改版。

## RPG Maker 2000/2003 与 RGSS 提取器

这两组使用独立 extractor ID、格式版本和注册项；旧版二进制解析与归档解密只在 `core/translation/extraction` 内调用，解析器通过已授权的 `ReadOnlyGameSource` 取得单个相对路径的字节，不访问文件系统路径、不写出解密内容、不执行 Ruby/RPG Maker 脚本。

| 引擎代际 | `extractorId` | `formatVersion` | 目录前置条件与文件覆盖 |
| --- | --- | --- | --- |
| RPG Maker 2000/2003 | `rpgmaker-2000-2003-lcf-v1` | `rpg-maker-2000-2003-lcf-v1` | 根目录必须同时有 `RPG_RT.ldb` 和 `RPG_RT.lmt`；读取这两份 LCF 文件及根目录 `Map数字.lmu`。数据库中的 `ldb_id` 由解析库用于区分 2000/2003 的数据布局。 |
| RPG Maker XP/VX/VX Ace/mkxp-z（RGSS） | `rpgmaker-rgss-data-v1` | `rgss-rxdata-rvdata-rvdata2-v1` | 解密包内资源优先使用 `Data/` 下 `System` 与同一代扩展名的白名单数据库和 `Map数字`（`.rxdata` / `.rvdata` / `.rvdata2`）；解密包则支持根目录单个 `.rgssad` / `.rgss2a` / `.rgss3a`，只解析包内 `Data/` 白名单。mkxp-z 沿用其运行游戏的 RGSS 数据格式，没有单独解析器。 |

2000/2003 与 RGSS 使用翻译域的专用来源 ID（`TranslationExtractorEngineIds`），不新增 `EngineType` 或改变游戏扫描、启动和运行时支持。

- RPG Maker 2000/2003 的 LCF 字符串按 Shift-JIS 解码；只把模型中已知文本字段的字节数组解码为文本，保留数字参数及未知字段。对话（10110/20110）按连续行组成一条，选项（20140）及英雄名称/称号命令（10610/10620）单独提取。
- RGSS 解析 Marshal 数据中的已知数据库字符串和事件命令（102 选项、401 对话、405 滚动文本、320/324/325 角色文本）；跳过脚本、注释、未知命令参数及不在白名单内的文件。归档路径先规范化并拒绝绝对路径、盘符及 `.` / `..` 段；仅接收 `Data/` 下对应代际扩展名的已知资源。
- RGSS 目录须有唯一 `Data/System` 文件；若没有 `Data/`，根目录须恰有一个支持的 RGSS 归档。混合代际扩展名、缺少 System、多个归档均按不支持格式处理。每个直接文件最多 32 MiB；归档最多 64 MiB 输入、50,000 项、每资源 32 MiB、解码输出最多 64 MiB。一个归档作为单文件检查点提交，归档内资源条目仍用各自相对路径和 JSON Pointer 生成稳定 `sourceKey`。
- Android 解码桥使用 `rvpacker-txt-rs-lib 19.0.1` 的内存 JSON 解析和 `rpgmad-lib 7.0.0` 的流式归档解密接口；两者 crates.io 清单标注 WTFPL，源仓库分别为 [`rvpacker-txt-rs-lib`](https://github.com/RPG-Maker-Translation-Tools/rvpacker-txt-rs-lib) 与 [`rpgm-archive-decrypter-lib`](https://github.com/RPG-Maker-Translation-Tools/rpgm-archive-decrypter-lib)。桌面 CLI 不作为应用依赖。`app/src/main/rust/Cargo.lock` 固定完整依赖版本，`build-android.ps1` 使用 NDK 28 交叉编译 arm64 JNI 库；当前不提供其它 ABI 的该解码库。
- 解析库测试覆盖合成 LCF 错误输入、Shift-JIS 文本归一化及合成归档解密/路径筛选；另用锁定版本的解析库对本机 RPGMTools 的 RM2K、RMXP、RMVX、RMVXACE 测试资源及 EasyRPG-TestGame 的 2003 样本做过只读解析冒烟（分别成功解析 LDB/LMT/LMU 与 16/15/16 个白名单 Marshal 资源）。Kotlin 合成夹具覆盖独立注册、文件发现、事件提取与稳定 key。该冒烟直接调用解析库 API，不是通过 Android SAF/JNI 的游戏内验收；当前没有真实加密 RGSS 游戏归档、商业游戏或用户提供游戏样本验证，也没有设备 SAF 验收。解析测试通过不代表真实游戏覆盖完整。

尚未覆盖的旧版内容包括插件自定义数据、脚本中内嵌文本、图片文字、运行时生成文本、压缩/变体归档、非标准 Data 目录结构、混合代际资源、其它 RPG Maker 代际及修改版格式。归档解密只在内存中读取白名单资源；归档超过上限或含有格式错误的白名单资源时任务失败并保留此前已提交文件检查点。

## 项目交换格式

工作台当前唯一的项目文件格式为 MTool JSON：根 JSON 对象以原文为键、译文为值。文件只保存文本映射，不含项目名称、引擎、语言、来源文件位置、任务、术语表、密钥或校对状态；导入名称取自文件名，条目的 `sourceKey` 由导入文本确定性生成。

文档上限为 32 MiB、最多 200,000 项；空原文和非字符串译文拒绝导入。空译文导入为未翻译条目；导出会保留未翻译原文并将译文写为空字符串。重复原文和相同译文会合并；同一原文存在不同非空译文时导出失败，不静默覆盖。

旧版 Tyranor JSON 与 CSV 编解码仍留在 `TranslationProjectCodec` 供历史兼容，但不出现在当前添加/导出工作流。MTool JSON 导出文件不代表 TYN 已具备应用内运行时译表加载通路。

## 翻译服务配置

- 当前应用设置提供两类服务档案：机器翻译（17 个固定协议 adapter）与 AI 翻译（OpenAI Chat Completions、OpenAI Responses API、Gemini Interactions v1、Anthropic Claude Messages API）。AI 服务列表提供 OpenAI、DeepSeek、Gemini 与 Claude 四个内置模板；自定义 API 可在 Chat Completions、OpenAI Responses 与 Anthropic Messages 三种协议中选择并配置兼容服务地址；Gemini 使用独立官方模板，已保存的其它服务档案仍显示以便管理。Chat Completions 模板复用同一个协议 adapter。能力、默认协议地址、供应商凭据、批次上限和稳定性限制见[翻译服务配置与协议适配实现说明](翻译服务配置与协议适配实现说明.md)。服务档案与实际 adapter 分开管理；未列出的服务商不因模板或名称显示而视为已接入。
- 服务档案保存显示名、协议 ID、根地址、模型 ID、翻译/校对提示词、启用状态与配置修订。地址仅接受 HTTP/HTTPS；拒绝 URL userinfo、query、fragment 和 `.` / `..` 路径段。HTTP 仅适合用户信任的本机或局域网服务，公网服务应使用 HTTPS。
- 模型目录由 adapter 请求根地址下的 `GET /models`；任务 API 由 `POST /chat/completions` 组成。可以手动填写模型 ID。模型列表请求成功不代表模型具有翻译权限。
- API Key 不进入 Room、任务快照或导出。翻译域独立存储用 Android Keystore AES/GCM 加密的密文，并将 `translation_service_secrets.xml` 从云备份与设备迁移排除；服务配置保存版本化 `secretRef`。密文解密失败会保留密文并返回错误，不静默清除。
- 两类服务共用安全 transport 和持久任务闭环；17 种机器翻译 adapter 按各自供应商协议请求，机器翻译凭据使用加密 bundle，不出现任意 URL 或模型输入。必应适配器依赖网页会话令牌流程，稳定性有限。JVM 合成回归不构成真实供应商连通性/兼容性验收。

## 当前验证证据与待验收项

- JVM 合成夹具覆盖 MTool JSON 导入/导出、历史 CSV/版本化 JSON 编解码与 RPG Maker MV/MZ JSON、2000/2003 LCF 输出形状、RGSS Marshal JSON、明文 Data 与归档计划的事件提取；相关测试为 `MToolJsonImporterTest`、`MToolJsonExporterTest`、`TranslationProjectCodecTest`、`RpgMakerTextExtractorTest`。Rust 原生桥的格式和归档测试从 `app/src/main/rust` 执行 `cargo test`。
- 服务档案固定主机校验、凭据 bundle、17 种机器翻译协议请求/响应与签名、能力过滤、OpenAI/Gemini 结构化响应及 OkHttp 调用取消有 JVM 回归；服务设计和限制见[翻译服务配置与协议适配实现说明](翻译服务配置与协议适配实现说明.md)。
- 合成夹具通过不证明真实游戏资源覆盖完整。MuMu 的 1920×1080 平板画面已检查工作台项目列表布局；这不代表手机布局、其他翻译页面、交互、无障碍或 SAF 流程已完成设备验收。当前没有真实 RPG Maker 游戏样本验收，也没有设备上的 SAF 授权撤销/恢复、通知权限、长时间后台运行或导出后游戏内显示验收。
- 译文人工编辑/确认、本地规则检查与 AI 校对建议已实现，范围、迁移、交互和验证见[翻译校对闭环实现说明](翻译校对闭环实现说明.md)。当前代码没有应用内运行时译表加载与交付通路，MTool 文件导出尚未通过真实游戏显示验收。其它引擎提取器尚未接入。
- 尚未完成设备侧 Android Keystore 加密及恢复后重新录入密钥验收；真实 AI 服务商请求也未验收。设备上的平板工作台布局检查不等同于服务连通性或端到端验收。
- AI 校对范围默认值仍属待产品确认事项；界面每次要求用户在规则命中项和全部已翻译项中显式选择，不预设默认值。机器翻译网页通道必应、Google 与有道已有 Medium Phone API 36 模拟器批量任务冒烟证据，详见 `SPEC.md`；其余真实机器翻译服务和真实 AI 服务商请求仍未验收。
