# 翻译批量任务实现说明

状态：本文记录阶段二批量翻译与 MTool exporter 的实现；阶段三校对功能见[翻译校对闭环实现说明](翻译校对闭环实现说明.md)。文中阶段二的 schema 和验证记录按阶段提交时点描述，不代表真实服务、真实游戏或 Android 设备验收已经完成。

## 工作台入口与服务列表

- 添加项目先选择提取、翻译或校对；提取时从引擎下拉列表选择引擎，翻译/校对时选择 CSV 或标准 JSON 导入。
- 翻译服务页面使用机器翻译和 AI 翻译两个分类；内置机器翻译列表只提供必应、小牛、火山、Azure、DeepL、百度和腾讯，已保存的其它协议档案仍保留显示以便管理。每个已实现模板显示独立卡片、配置状态和服务地址。点击配置进入完整页面；AI 高级设置也使用完整页面，AI 卡片额外显示协议与已填写模型，配置后可直接启用。自定义入口使用普通主按钮“添加自定义API”。
- 创建术语表只填写名称；从列表进入“编辑”后维护多条原文、译文与可选备注，支持连续添加、逐条修改和删除。

## 启动与配置快照

- 项目卡片从翻译服务 repository 提供的启用且已配置服务中选择服务，包括 12 个固定供应商 HTTPS 机器翻译 API、必应网页令牌适配器和 OpenAI Chat Completions、OpenAI Responses、Gemini Interactions、Anthropic Claude Messages AI 翻译。Chat Completions 厂商模板复用同一 adapter；机器翻译没有模型字段，AI 服务可获取模型目录或手动填写模型 ID。用户手动填写原文语言与目标语言，当前范围为待翻译条目。
- 开始任务时持久化服务 ID、服务配置 revision、协议 ID、根地址、模型 ID、`secretRef`、源/目标语言、系统/用户提示词、协议生成参数、`UNTRANSLATED` 范围以及术语表 revision 和内容快照。API Key 不进入 Room 任务快照。
- 服务停用或编辑后，已排队/运行任务仍按保存的快照执行。密钥使用版本化引用；密钥清理会保留任务快照仍引用的版本，项目删除后可清理不再引用的密钥。
- 开始任务要求项目存在待翻译条目、服务启用且配置完整、源/目标语言非空且不同。语言标识由用户填写，例如 `ja` 与 `zh-CN`。

## 批次执行、进度与恢复

- 提取与翻译共用 `translation-workbench-content-tasks` 唯一 WorkManager drain 队列，跨项目串行；同一项目同一时间最多一个活动内容任务。进入工作台时从 Room 补排仍为 `QUEUED` / `RUNNING` 的任务。
- 任务处理器最多提交 50 条/请求，并进一步遵循 adapter 上限；单条机器翻译协议逐条提交。支持稳定条目 ID 的 AI 响应按 ID 校验；常见供应商翻译 API 不接收 TYN ID，adapter 按同请求输入顺序绑定响应。缺失、额外响应、空译文及控制码/占位符/换行损坏分别识别。通过校验的译文与失败条目状态、失败计数和任务检查点在同一个 Room 事务提交。
- 任务/项目/条目状态独立管理。条目错误码保存在条目行；总体请求错误保存为任务失败码。已提交译文不因取消、进程中断或后续请求失败而回滚。取消会先持久化任务状态，再取消唯一 WorkManager 链，因此协程取消会传递到 OkHttp `Call.cancel()`；剩余项目任务随后重新入队。
- 进程中断后，Worker 依据持久化条目状态继续当前任务，已翻译或已记录失败的条目不会在同一任务里再次提交。用户选择「重试未完成项」时创建新任务，继承原任务快照，将失败条目重置为待翻译，并只处理待翻译/失败条目；已完成译文保持不变。
- Worker 临时 progress 只用于通知；卡片展示的完成数、总数和失败数来自 `translation_tasks`。鉴权、配额、协议错误和网络错误以类型化服务错误码结束任务，不做无界自动重试，用户可显式重试。

## 工作台术语表（后续增补）

- 当前工作台支持命名术语表列表：新建时只填写名称；从列表点“编辑”后管理术语列表，可连续添加多条原文、译文与可选备注，也可逐条修改或删除；翻译启动窗口使用下拉框选择术语表。
- 每份术语表最多 100 项；每个源/目标术语最多 120 字符，备注最多 500 字符，合计文本最多 8,000 字符；同一术语表内源术语不区分大小写去重。
- `translation_workbench.db` schema v7 通过 `translation_glossaries` 和 `translation_glossary_entries` 持久化可复用术语表。v6→v7 把既有项目术语复制为独立命名术语表并设置为该项目的选中术语表；旧表暂时保留兼容。
- 翻译/AI 校对任务快照保存所选术语表 ID、名称、revision 和条目内容。编辑或删除术语表不会修改已启动任务的快照；删除当前选中术语表后，项目外键置空。

## MTool JSON 文件导出

- MV/MZ 项目可单独导出 MTool JSON。格式是根 JSON 对象，键为来源文本，值为非空译文；不含任务、服务、术语表或校对数据。未翻译条目会跳过，相同来源文本且译文相同的条目合并。
- MTool 映射以来源文本作为键，无法表达同一来源文本的多个不同译文；遇到冲突时 exporter 返回类型化错误并停止写出，不按顺序覆盖。
- 当前分支不包含设计文档引用的 `core/engine/translation/TranslationCatalog`、`TranslationMapProvider` 或 engine 侧 `TranslationMapSubscription`；本功能只生成用户选择位置的 MTool JSON 文件，不自动接入 TYN 的运行时加载/交付。该格式生成有合成样例回归，但没有真实 MTool 应用或游戏内显示验收。

## 持久化与迁移

阶段二提交时工作台数据库为 `translation_workbench.db` schema v5；v5→v6 的校对表与迁移见阶段三说明；当前工作区已到 schema v8；v7→v8 为服务档案增加翻译/校对用户提示词与可选生成参数。任务快照和进度均为 Room 数据；密钥仍独立存放于 Keystore 加密的翻译专用偏好文件。

## 验证与限制

- 服务扩展历史验证包括 `:app:compileDebugKotlin`；当前机器翻译适配器与固定主机检查、OpenAI/Gemini/Anthropic、任务快照和 transport 的 JVM 专项回归结果以当前提交说明为准。
- 尚未验证迁移在真实旧版数据库/设备上的执行、Android Keystore 真机行为、真实 OpenAI/兼容端点、长时间后台调度、手机/平板布局及真实 MV/MZ 游戏。
- 人工译文编辑/确认、本地规则检查和 AI 校对由阶段三补齐。AI 校对范围默认值仍待产品确认，工作台对校对范围要求用户每次显式选择。真实供应商账号、网络区域、配额与翻译质量尚未验收；必应网页接口可能因上游变化失效。
