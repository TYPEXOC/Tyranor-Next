# 翻译批量任务实现说明

状态：本文记录阶段二批量翻译与 MTool exporter 的实现；阶段三校对功能见[翻译校对闭环实现说明](翻译校对闭环实现说明.md)。文中阶段二的 schema 和验证记录按阶段提交时点描述，不代表真实服务、真实游戏或 Android 设备验收已经完成。

## 工作台入口与服务列表

- 项目列表使用 Miuix `TabRowWithContour` 按全部、进行中、可继续和已翻译筛选，并展示各自项目数；进行中按排队/运行任务或项目处理中状态判定，可继续为非活动项目，已翻译要求所有条目都有译文。分类允许重叠，筛选无结果时显示分类空状态。
- 术语卡片分行标识原文、译文和备注；编辑/删除使用右侧纵向排列的独立按钮。备注标签始终显示，区域有固定高度，新增备注不会改变术语卡片高度。单条术语保存后立即写入；名称修改在返回时自动保存，返回不再询问是否保存。
- 添加项目表单使用下拉选择提取、翻译或校对，并在同一表单展示对应的引擎/文件格式；提取显示常驻游戏目录路径小卡片，翻译和校对显示常驻项目文件路径小卡片，未选择时显示提示，选中后显示 SAF 路径或文件名，右侧选择按钮作为附加操作。操作和游戏引擎均显示不超过一行的辅助说明；只有提取可选引擎，翻译和校对时引擎选项置灰。弹窗内下拉菜单使用独立窗口承载，并使用 TYN 弹窗色板适配明暗模式；通过系统 SAF 选择器选好目录或项目文件后返回原表单确认添加。
- 翻译服务页面使用机器翻译和 AI 翻译两个分类；内置机器翻译列表提供 13 个模板入口，已保存的其它协议档案仍保留显示以便管理。每个已实现模板显示独立卡片、配置状态和服务地址。点击配置进入完整页面；AI 高级设置也使用完整页面，AI 卡片额外显示协议与已填写模型，配置后可直接启用。“添加自定义 API”使用 Miuix Scaffold 浮动加号按钮，仅在 AI 分类显示。
- 翻译服务分类内容使用共享 `TabPagerState` / `TabPageMotion`：增强动效下水平滑动，普通动效下即时切换。翻译服务列表页自身通过 `AppScreenActivity` 接入统一的页面进入/返回转场；服务配置、任务设置、高级设置和自定义参数目前由同一 Activity 内的条件分支显示，彼此切换尚无标准侧推动效。工作台分类用于项目筛选，卡片使用统一列表项动效。
- 新建术语表先在弹窗填写名称并保存，随后进入完整术语列表页。列表卡片右侧提供编辑与删除；详情页可修改名称、查看多条原文/译文和备注，使用 Miuix Scaffold 浮动加号按钮添加术语；单条术语通过弹窗维护并立即保存，名称修改在返回时自动保存。

## 启动与配置快照

- 项目卡片从翻译服务 repository 提供的启用且已配置服务中选择服务，包括 17 种机器翻译协议 adapter 和 OpenAI Chat Completions、OpenAI Responses、Gemini Interactions、Anthropic Claude Messages AI 翻译。机器翻译配置页提供 13 个内置入口；Chat Completions 厂商模板复用同一 adapter。机器翻译没有模型字段，AI 服务可获取模型目录或手动填写模型 ID。用户手动填写原文语言与目标语言，当前范围为待翻译条目。
- 开始任务时持久化服务 ID、服务配置 revision、协议 ID、根地址、模型 ID、`secretRef`、源/目标语言、系统/用户提示词、协议生成参数、按服务类别设置的任务参数、`UNTRANSLATED` 范围以及术语表 revision 和内容快照。API Key 不进入 Room 任务快照。
- 服务停用或编辑后，已排队/运行任务仍按保存的快照执行。密钥使用版本化引用；密钥清理会保留任务快照仍引用的版本，项目删除后可清理不再引用的密钥。
- 开始任务要求项目存在待翻译条目、服务启用且配置完整、源/目标语言非空且不同。语言标识由用户填写，例如 `ja` 与 `zh-CN`。

## 批次执行、进度与恢复

- 提取与翻译共用 `translation-workbench-content-tasks` 唯一 WorkManager drain 队列，跨项目串行；同一项目同一时间最多一个活动内容任务。进入工作台时从 Room 补排仍为 `QUEUED` / `RUNNING` 的任务。
- 机器翻译每批条数、批次并发、请求间隔和 RPM，以及 AI 每批条数、批次并发与请求间隔，按服务档案单独保存并写入任务快照。机器翻译默认 30 条、并发 2、间隔 0.2 秒、RPM 0；AI 默认每批 20 条、并发 1、间隔 0 秒。两类任务均按条目数量拆批；AI Token 上限不再提供独立设置卡片，可通过自定义请求体填写。高级设置中的回显对齐开关默认关闭；开启后任务快照固定该开关，逐条校验模型返回的 `src` 原文回显，错位项失败且可重试。当前任务队列跨项目串行，AI 并发设置控制当前任务内并行请求。
- 任务处理器最多提交 50 条/请求，并进一步遵循 adapter 上限及机器翻译服务的批量设置；AI 请求按服务设置的条目数量拆分。支持稳定条目 ID 的 AI 响应按 ID 校验；常见供应商翻译 API 不接收 TYN ID，adapter 按同请求输入顺序绑定响应。缺失、额外响应、空译文及控制码/占位符/换行损坏分别识别。通过校验的译文与失败条目状态、失败计数和任务检查点在同一个 Room 事务提交。
- 任务/项目/条目状态独立管理。条目错误码保存在条目行；总体请求错误保存为任务失败码。已提交译文不因取消、进程中断或后续请求失败而回滚。取消会先持久化任务状态，再取消唯一 WorkManager 链，因此协程取消会传递到 OkHttp `Call.cancel()`；剩余项目任务随后重新入队。
- 进程中断后，Worker 依据持久化条目状态继续当前任务，已翻译或已记录失败的条目不会在同一任务里再次提交。用户选择「重试未完成项」时创建新任务，继承原任务快照，将失败条目重置为待翻译，并只处理待翻译/失败条目；已完成译文保持不变。
- Worker 临时 progress 只用于通知；卡片展示的完成数、总数和失败数来自 `translation_tasks`。鉴权、配额、协议错误和网络错误以类型化服务错误码结束任务，不做无界自动重试，用户可显式重试。

## 工作台术语表（后续增补）

- 当前工作台支持命名术语表列表：新建时在弹窗填写名称并进入独立详情页；列表卡片右侧提供编辑和删除，详情页展示术语列表，可连续添加多条原文、译文与可选备注，也可逐条修改或删除；“添加术语”通过 Miuix Scaffold 浮动加号按钮打开单条编辑弹窗，保存后立即提交该术语，术语表名称在返回时自动保存；翻译启动窗口使用下拉框选择术语表。
- 每份术语表最多 100 项；每个源/目标术语最多 120 字符，备注最多 500 字符，合计文本最多 8,000 字符；同一术语表内源术语不区分大小写去重。
- `translation_workbench.db` schema v7 通过 `translation_glossaries` 和 `translation_glossary_entries` 持久化可复用术语表。v6→v7 把既有项目术语复制为独立命名术语表并设置为该项目的选中术语表；旧表暂时保留兼容。
- 翻译/AI 校对任务快照保存所选术语表 ID、名称、revision 和条目内容。编辑或删除术语表不会修改已启动任务的快照；删除当前选中术语表后，项目外键置空。

## MTool JSON 项目交换

- 工作台以 MTool JSON 作为唯一用户可选的文本项目导入/导出格式。格式是根 JSON 对象，键为原文，值为译文；文件不带项目/引擎/语言元数据。导入项目名称来自文件名，sourceKey 由原文集合确定性生成。
- 未翻译条目导出为空字符串；导入时空译文作为未翻译条目。相同原文和相同译文会合并；若同一原文存在不同非空译文，导出以类型化错误终止，不按顺序覆盖。
- 该映射导出适用于工作台的所有项目，不代表 TYN 已具备应用内运行时译表加载通路。合成样例回归已覆盖导入/导出映射，尚未完成真实 MTool 应用或游戏内显示验收。

## 持久化与迁移

阶段二提交时工作台数据库为 `translation_workbench.db` schema v5；此后 v5→v6 增加校对记录，v6→v7 增加命名术语表，v7→v8 增加用户提示词与协议生成参数，v8→v9 新建并启用网页机器翻译档案，v9→v10 增加服务级任务设置 JSON。任务快照和进度均为 Room 数据；密钥仍独立存放于 Keystore 加密的翻译专用偏好文件。

## 验证与限制

- 服务扩展历史验证包括 `:app:compileDebugKotlin`；当前机器翻译适配器与固定主机检查、OpenAI/Gemini/Anthropic、任务快照和 transport 的 JVM 专项回归结果以当前提交说明为准。
- 尚未验证迁移在真实旧版数据库/设备上的执行、Android Keystore 真机行为、真实 OpenAI/兼容端点、长时间后台调度、手机/平板布局及真实 MV/MZ 游戏。
- 人工译文编辑/确认、本地规则检查和 AI 校对由阶段三补齐。AI 校对范围默认值仍待产品确认，工作台对校对范围要求用户每次显式选择。真实供应商账号、网络区域、配额与翻译质量尚未验收；必应网页接口可能因上游变化失效。
