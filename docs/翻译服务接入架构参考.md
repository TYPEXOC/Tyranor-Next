# 翻译服务接入架构参考

> 状态：设计参考，尚未实现。核对日期：2026-11-16。本文基于当前仓库实现与翻译工作台原型整理，不代表服务接入已经存在。

本文说明翻译服务配置、协议适配、模型列表、API 请求、安全存储和任务调用的边界。工作台项目与任务模型见[翻译工作台架构设计](翻译工作台架构设计.md)，批量任务和失败续跑的开源参考见[翻译任务开源项目参考](翻译任务开源项目参考.md)，引擎文本提取器参考见[翻译文本提取开源参考](翻译文本提取开源参考.md)。

## 1. TYN 当前状态

| 能力 | 当前实现 | 对服务接入的意义 |
| --- | --- | --- |
| 游戏运行时译表 | `core/engine/translation/TranslationCatalog` 发现并读取 MTool JSON 等运行时译表；`TranslationStorage` 管理私有译表文件 | 这是“加载已有译文”，不是翻译 API、工作台项目或服务管理，不应把网络调用塞进该包 |
| HTTP 客户端 | Gradle 已引入 OkHttp 5.5.0；`WebDavClient` 使用自己的 OkHttp 配置。更新器、授权和其他网络功能还可见 `HttpURLConnection` | 没有可直接复用的全局网络门面。先在翻译域内封装 transport，不借用 WebDAV 专用客户端，也不趁机重构全 App 网络 |
| 服务配置 | 尚无翻译服务档案、启停列表、模型发现或服务配置页面 | 需要新建翻译域 repository 和设置 UI；工作台的服务选择器订阅同一数据源 |
| 配置存储 | `AppSettingsStore` 是全局应用设置的 SharedPreferences/Flow 存储 | 不宜把多条服务、模型缓存和提示词堆成一组全局偏好键 |
| 凭据安全 | `SecureAuthStore` 面向 Hikarinagi 登录令牌；`WebDavSettingsStore` 是 WebDAV 专用配置加密存储，均使用 Android Keystore 相关机制 | 可学习 AES/GCM、错误处理和密文保留方式，但不能直接复用其固定字段、别名或业务接口 |
| 网络权限 | Manifest 已有 `INTERNET` 权限和 `usesCleartextTraffic="true"` | 这不代表服务配置可以默认使用明文。公网服务仍应优先 HTTPS；HTTP 主要用于用户明确配置的本机/LAN 服务 |

因此，新功能应新增 `core/translation/service`，与现有 `core/engine/translation` 并列。前者管理“向服务发送文本并接收结果”，后者继续管理“把已有译表提供给运行时引擎”。

## 2. 服务分类与产品约束

### 传统机器翻译

- 设置页的“传统机器翻译”列表维护 TYN 提供的固定服务模板，例如 DeepL、Google Cloud Translation、Microsoft Translator、百度翻译。
- 用户只能配置模板支持的凭据、区域或端点，并决定是否启用；不提供任意添加机器翻译协议的入口。
- 机器翻译服务只参与“翻译”，不能出现在 AI 校对服务选择器中。

### AI 翻译 API

- API 通信协议由 TYN 选定、实现、测试和维护；服务商模板只保存协议对应的初始地址、认证方式和模型建议。设置页的“AI 翻译 API”列表包含这些预置模板与用户自定义的服务档案，保存后仍需单独启用。
- 首期 AI 协议族建议由 TYN 实现并维护：OpenAI 兼容 Chat Completions、Gemini API、Anthropic Messages（Claude）。服务商若兼容其中一种，配置对应协议和服务地址即可，不需要为每一家再写一套客户端。
- OpenAI、DeepSeek 等可共用 OpenAI 兼容协议适配器；Gemini、Claude 使用各自的原生协议适配器。用户添加“自定义 AI API”时选择受支持的协议，并配置地址、密钥与模型。
- “自定义 AI API”指用户创建一个服务档案，并从 TYN 已实现的协议模板中选择接口类型。首期不承诺任意 HTTP 请求头、任意 JSON 请求体或任意响应 JSON 的低代码映射。
- 云端 API 与另一 APK/本机服务暴露的 API 使用同一接入方式。若服务遵循 OpenAI 兼容协议，选 OpenAI 兼容接口并填入服务地址、模型 ID 和可选密钥；TYN 不在进程内运行模型，也不将它显示为独立“本地模型”服务。
- Android 设备上的 `127.0.0.1` / `localhost` 指当前设备自身。若 API 服务运行在同一设备上，可以使用其监听端口；若运行在局域网电脑上，应填写电脑的局域网地址。公网地址使用 HTTPS。

OpenAI 兼容接口在许多服务商中常见，适合以一个协议适配器覆盖多个服务；具体兼容字段、模型目录和思考参数仍需逐服务验证，因此覆盖比例只作为目标，不作为兼容保证。

### 选择器与默认值

- 设置页服务列表是服务状态的唯一来源；每条服务有一个启用开关。服务选择器直接订阅同一 repository 的 `Flow`，仅列出已启用且能力匹配的档案。
- 翻译和 AI 校对在各自开始面板中选择服务，不在设置页设置“默认翻译服务”或“默认校对服务”。
- 服务选择器显示用户设置的服务名称，不追加模型 ID。模型属于服务配置详情。
- 服务档案保存成功或开关变化后，所有订阅者立即看到更新；不得要求退出重进页面才刷新。

## 3. 分层与数据流

```text
设置 UI ──保存/启停──┐
                    ├── TranslationServiceRepository (Flow + 命令)
工作台 UI ──选择服务─┘                  │
                                       ├── ServicePresetRegistry
翻译/校对任务 ──稳定条目请求── TranslationProviderRegistry
                                                │
                              ┌─────────────────┴────────────────┐
                              │                                  │
                    机器翻译协议 Adapter                  AI 协议 Adapter
                    DeepL / Google / …         OpenAI 兼容 / Gemini / Claude
                              └─────────────────┬────────────────┘
                                                │
                                   TranslationHttpTransport
                                   OkHttp + 取消/超时/错误映射
```

建议的 core 目录：

```text
core/translation/service/
├── TranslationServiceProfile.kt       # 非敏感服务配置 DTO
├── TranslationServiceRepository.kt    # 服务档案查询、保存、启停 Flow
├── TranslationServicePreset.kt        # 厂商/服务模板，只提供档案初始值
├── TranslationProtocolAdapter.kt     # 协议级翻译、校对、测试和可选模型目录能力
├── TranslationProtocolRegistry.kt    # 按 protocolId 选择 TYN 自己维护的 adapter
├── TranslationServiceError.kt         # 类型化错误码
├── model/                              # 模型目录结果与能力描述
├── secret/                             # API 密钥安全存储与版本引用
├── transport/                          # 翻译域自己的 OkHttp transport
├── protocol/
│   ├── machine/                        # DeepL、Google 等固定机器翻译协议
│   └── ai/                             # OpenAI 兼容、Gemini、Anthropic Messages
└── preset/                             # OpenAI、DeepSeek、Claude 等服务档案模板
```

UI 放在 `ui/settings/translation/` 管理服务列表与配置，在翻译/校对开始面板选择服务。Core 不依赖 Compose；全局可观察状态使用 `Flow`/`StateFlow`，UI 收集状态。当前没有全 App 通用 DI 容器，首期可沿用项目已有的 repository/facade 构造方式，不为这一功能引入新的 DI 框架。

运行链路：

1. 设置页读取服务档案，用户保存配置，再显式启用服务。
2. 工作台从 repository 获取已启用、适用于当前操作的服务档案。
3. 用户开始任务时，任务保存服务 ID、配置修订号、协议、模型、语言、批次与提示词等非秘密快照。
4. Worker 通过 registry 创建对应 adapter；adapter 读取该修订所需密钥引用，组装协议请求。
5. transport 执行 HTTP 请求，adapter 将厂商响应转换为统一的条目结果或类型化错误。
6. Worker 按稳定条目 ID 将成功结果与检查点写入工作台数据库；部分失败可单独重试。

## 4. 服务档案与持久化

通信协议和服务商模板要区分：协议适配器由 TYN 实现；模板是不可变的初始建议；用户保存后得到独立服务档案。许多服务商共用一种协议，因此新增一个兼容服务商通常只需增加模板或允许用户创建自定义档案。建议档案包含：

| 字段 | 用途 |
| --- | --- |
| `serviceId` | TYN 生成的稳定 ID，不使用服务名称作为主键 |
| `displayName` | 列表与任务选择器展示名称，允许用户修改 |
| `category` | `MACHINE_TRANSLATION` 或 `AI_API` |
| `protocolId` / `protocolVersion` | 选择具体请求与响应适配器，例如 `openai-compatible-chat`、`gemini-api`、`anthropic-messages` |
| `presetId` | 可选服务模板标识，例如 OpenAI、DeepSeek、Claude；用户自定义服务可为空 |
| `baseUrl` | 服务根地址；由 adapter 按协议构造端点，避免 UI 拼接固定路径 |
| `modelId` | AI 模型 ID；机器翻译协议不需要时为空 |
| `enabled` / `configured` | 区分“已填写配置”与“允许任务选择” |
| `timeout` / `maxConcurrency` | 服务级请求上限；任务仍需服从全局队列规则 |
| `thinkingEffort` | AI 可选项；仅当协议/服务声明支持时发送，关闭时不发送参数 |
| `translationPrompt` / `proofreadPrompt` | 可分别编辑的提示词；UI 默认折叠编辑区 |
| `revision` / 时间戳 | 配置变更检测和运行任务快照 |
| `secretRef` | 指向加密密钥存储的引用，不包含密钥本身 |

服务元数据建议放入前一份架构设计提出的 `translation_workbench.db` 服务表；模型列表作为可失效缓存，不作为服务可用性的唯一依据。API Key、Secret、私有认证头不进入 Room、普通设置、任务快照、日志或导出文件。用户改名不应改变服务 ID，也不应破坏任务关联。

密钥放在翻译域专用的安全存储中，使用 Android Keystore + AES/GCM；按服务 ID 和密钥修订保存，任务只保存密钥引用。活动任务继续使用启动时的配置修订；替换密钥时，旧密钥版本在引用任务结束后清理。若旧密钥不可恢复，任务以明确的凭据错误结束，不自动换用新服务或静默使用新密钥。密钥存储文件要像现有 WebDAV/OAuth 密文一样从 `backup_rules.xml` 和 `data_extraction_rules.xml` 的云备份、设备迁移规则中排除；换机后提示用户重新填写密钥。

解密或 Keystore 暂时失败时保留密文，不得因读取失败就自动清空服务档案或密钥数据。`SecureAuthStore` 与 `WebDavSettingsStore` 是实现行为的参考，不是可直接调用的通用凭据 API。

## 5. TYN 协议适配器、服务模板与模型列表

### TYN 管协议，服务商复用协议

服务商名称不是协议。TYN 为一组通信协议实现 `TranslationProtocolAdapter`，再用多个服务模板填写端点、认证方式和模型建议。新增同协议服务商时不复制网络客户端；新增协议时才由 TYN 增加 adapter、能力声明和协议回归覆盖。

- `OPENAI_COMPATIBLE_CHAT`：以 OpenAI Chat Completions 兼容请求/响应为边界，服务地址、API Key（可选）、模型 ID 可配置。OpenAI、DeepSeek 及兼容网关可共用该 adapter；厂商扩展字段通过能力声明或明确配置处理，不能假定兼容百分之百。
- `GEMINI_API`：TYN 维护 Google Gemini 原生 API adapter；按支持的 API 版本实现认证、模型目录、请求、响应和错误映射。
- `ANTHROPIC_MESSAGES`：TYN 维护 Anthropic Messages API adapter，供 Claude API 使用；按支持的 API 版本实现认证、模型目录、请求、响应和错误映射。
- `DEEPL`、`GOOGLE_CLOUD_TRANSLATION`、`MICROSOFT_TRANSLATOR`、`BAIDU_TRANSLATE`：分别采用各自固定协议，不伪装成 OpenAI Chat API。传统服务通常无需用户选 LLM 模型。

预置服务只是填写器：OpenAI 和 DeepSeek 模板指向 `OPENAI_COMPATIBLE_CHAT`，Claude 模板指向 `ANTHROPIC_MESSAGES`，Gemini 模板指向 `GEMINI_API`；用户仍可修改服务名称、地址和模型。新服务若已有兼容协议，新增模板或自定义档案即可；只有出现新通信协议时才新增 TYN adapter。协议 ID 应稳定、可迁移，并在切换协议时清理或提示重填不兼容字段。

GalTransl 的公开配置使用一个 OpenAI-Compatible 后端配置多组 token、endpoint 和 model，可覆盖 DeepSeek、OpenRouter 等服务；Translator++ 的项目文档同时列出 OpenAI、Claude、Gemini 和 OpenAI-compatible gateway。它们支持“少量协议适配器 + 多个服务配置”的架构取向，但服务兼容能力应由 TYN 自己验证，不把开源项目列出的提供商数量当作 TYN 的兼容承诺。[GalTransl 后端配置](https://github.com/GalTransl/GalTransl/blob/main/README_EN.md) · [Translator++ 支持的服务](https://github.com/alwansan/TranslatorPlusPlus)

### 获取模型

- 服务若声明支持 `listModels`，配置页提供“获取模型”操作；成功后报告模型数量，并把结果放进模型选择器。
- OpenAI-compatible adapter 可尝试 `/models`，但模型目录中不一定全是可用于文本翻译的模型。必要时按模型能力过滤；无法可靠识别能力时允许用户自行选择。
- 不能获取模型时，显示可理解的失败原因，并保留“手动输入模型 ID”入口。输入模型 ID 应通过单独弹出的输入框完成，不把“手动输入……”伪装成真实模型选项。
- 模型目录请求失败不应阻止保存服务；若用户手动填入有效模型 ID，仍可保存、测试和启用。
- 模型列表与连接测试是不同动作。列出模型成功不保证翻译权限或模型可用；模型列表不支持时，连接测试走 adapter 的轻量验证策略。

模型清单接口会随服务协议变化；OpenAI Chat Completions、Gemini API、Anthropic Messages 都有各自请求/响应及版本约束。接入时应以供应方最新官方文档为准，并固定 TYN 实际支持的协议版本。[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[Gemini API 文档](https://ai.google.dev/gemini-api/docs)、[Anthropic Messages](https://docs.anthropic.com/en/api/messages)、[Google Cloud Translation v2](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate)。

## 6. 统一翻译请求与结果

协议 adapter 对外使用与厂商无关的数据结构：

```kotlin
data class TranslationInput(
    val entryId: String,
    val sourceText: String,
    val sourceLanguage: String?,
    val targetLanguage: String,
    val context: String?,
    val terminology: List<TermEntry>,
)

data class TranslationOutput(
    val entryId: String,
    val translatedText: String,
    val usage: UsageInfo? = null,
)
```

实际 DTO 放在 Kotlin 文件中时再根据现有模块依赖调整；这里强调的是字段和职责。AI 翻译和 AI 校对可以共用 transport 与协议 adapter，但通过不同操作类型与不同提示词构造请求。机器翻译通常只实现翻译能力。

- 请求必须保留稳定条目 ID、语言和术语，必要时附来源上下文；不要让 UI 直接把一段拼接好的 prompt 当作任务数据。
- 结果必须能映射回输入条目。若上游只按顺序返回，adapter 需校验响应数量与顺序；若采用模型结构化输出，也要验证缺失、重复、未知 ID 和格式损坏。
- 保留占位符、控制码和换行的规则由翻译域统一校验。发现格式损坏时不能把坏结果直接覆盖入库。
- 一批可返回部分成功。有效条目提交，失败条目保留错误码，任务重试只重做失败或未完成条目。
- AI 结果先保存为译文或校对建议；AI 校对建议不自动覆盖用户当前译文。

## 7. 网络调用、取消和错误

使用翻译域自己的 `TranslationHttpTransport` 与 OkHttp，不直接在 Composable、ViewModel 或任务队列中写 URLConnection。它负责：

- 请求执行、读取响应体上限、连接/读/写/整体调用超时；超时可按服务档案配置，但必须设上界。
- 将 coroutine 取消传播到底层 OkHttp `Call.cancel()`；取消是控制流，不转换成普通失败，也不触发重试。
- 默认不对鉴权失败、请求校验失败或模型不存在重试；限流和短暂服务错误才允许有上限的退避，并遵守服务端 `Retry-After`（若有）。
- 避免把 API Key 放到 URL query；禁止在日志、异常 detail 或分析事件中记录密钥、完整提示词和未经处理的游戏文本。
- 处理重定向时，不向不同主机转发 Authorization/API Key。需要跨主机跳转的服务由 adapter 明确、安全地处理。
- 对明文 HTTP 给出本机/LAN 提示；公网服务配置 HTTPS。环回地址在 Android 上是设备自身，并不指开发电脑。

Core 采用项目统一的类型化失败协议，建议至少覆盖：`INVALID_CONFIGURATION`、`SERVICE_DISABLED`、`UNSUPPORTED_PROTOCOL`、`NETWORK_UNAVAILABLE`、`TLS_FAILURE`、`TIMEOUT`、`AUTHENTICATION_FAILED`、`RATE_LIMITED`、`QUOTA_EXCEEDED`、`MODEL_NOT_FOUND`、`REQUEST_REJECTED`、`INVALID_RESPONSE`、`SECRET_UNAVAILABLE`。Core 返回错误码/DTO，不返回本地化文案；UI 维护中、英、日资源映射。UI 可以显示服务名、条目范围和简短错误，但不可显示密钥或完整服务端原始响应。

## 8. 配置页与工作台交互

设置中的服务列表：

1. 两个独立分类页签：“传统机器翻译”与“AI 翻译 API”。
2. AI 页签在服务列表上方放“添加自定义 AI API”；预置模板可以显示未配置/已配置/已启用状态。
3. 模板默认关闭；配置保存后回到列表，用户明确打开启用开关。配置按钮文案统一为“配置”。
4. 配置页允许选接口类型；API 地址、Key、模型选择与“获取模型”并排。模型无法获取时可手动输入 ID。
5. AI 配置有思考强度和提示词编辑；提示词区默认折叠。服务连接测试、模型获取、保存是不同操作。
6. 启用/保存/删除档案后，同一个 `StateFlow` 发出新列表；工作台选择器即时刷新。

翻译工作台开始面板：

- 源语言、目标语言、服务、翻译范围、批次和词库属于本次任务选择。
- 服务下拉只显示已启用且支持翻译的服务名称；选择后才创建并开始任务。
- 不提供全局默认服务下拉框，也不在校对编辑页重复展示服务设置。
- AI 校对开始面板只显示已启用且支持 AI 校对的 API 服务；手动校对不需要 AI API。
- 服务档案停用后，阻止新任务选择；已开始任务按开始时的配置修订执行并保留清晰状态。

## 9. 分阶段落地建议

1. **档案与安全存储**：Room 非秘密服务档案、服务商模板、协议 ID、启停 `Flow`、独立密钥存储、备份排除规则、服务列表与编辑页面。
2. **协议适配器闭环**：TYN 实现并维护 OpenAI-Compatible Chat、Gemini API、Anthropic Messages；完成连接测试、获取模型、手工模型 ID、批次翻译、请求取消和类型化错误。
3. **机器翻译 adapters**：每家服务独立协议、鉴权、语言映射、错误映射与真实接口验收，不建立“通用机器翻译 URL”。
4. **AI 任务能力**：提示词、术语表、思考强度能力判断，AI 翻译与可选 AI 校对请求，任务配置修订快照。
5. **新增协议的治理**：只有现有协议不能承载所需能力时才扩展新的 protocol adapter；服务商兼容已有协议时只增加预置模板或使用自定义服务档案。

自定义服务限定在 TYN 明确支持的协议，不实现任意 JSON 模板语言。OpenAI-compatible chat 能覆盖许多兼容服务，本机 API 也使用相同配置方式；Gemini 与 Claude 使用 TYN 自己的协议 adapter。TYN 应以经过验证的服务列表描述覆盖情况，不声明固定市场覆盖率。

## 10. 服务接入验收项

- 配置一条服务、保存、启用后，工作台订阅列表立即出现它；禁用后新任务选择器立即移除。
- 同一服务改显示名称后，列表和任务选择器显示新名称，关联 ID 与既有任务历史不变。
- 模型接口可用时显示获取数量与选择项；接口不可用时可手工填模型并保存，不会误把占位文字当模型 ID。
- 未配置密钥、无效密钥、模型不存在、限流、离线、超时和无效响应分别得到类型化状态，不崩溃、不丢已完成条目。
- 用户取消任务会取消 HTTP 请求并停止该批后续调度；不会把取消显示为网络错误。
- 批次部分失败时只重试失败条目；重启后按任务检查点恢复。
- 密钥不出现在数据库、任务快照、导出、日志或异常详情；密文读取失败时保留原数据。
- 公网 HTTP 配置有明确提示；环回地址与局域网地址分别在 Android 设备上验证。
- 以真实服务分别验收 OpenAI-compatible、Gemini、Claude 的成功请求、鉴权失败、模型列表、超时和取消；每个预置服务验证其所选协议兼容程度。机器翻译服务逐家验收。模拟响应测试不能替代真实服务验收。
